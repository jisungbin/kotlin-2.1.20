## visitComposableLambda 공부

> 함수가 람다이고, 반환 타입이 Unit이라면 실행되는 콜백

- `composableLambda`에 의해 기본적으로 restart group으로 감싸짐
- 컴파일러 플러그인으로 생성되는 기본 그룹은 없음
- 람다는 기본 인자를 가질 수 없으므로 항상 `$default`가 없음
- `???` 람다가 호출되는 공간에 따라 캡처 스코프가 달라지므로, skip이 불가능함

### 스킵 가능 조건 

- Unit 반환
- inline 람다가 아님
- 모든 trackedParameter가 불안정한 타입이 아님
- 기본값이 없는 불안정한 파라미터가 있다면, 해당 컴포저블은 절대 스킵할 수 없음

---

### 1. `$default`에 따라 기본 인자값 넣는 작업

람다는 기본 인자를 가질 수 없으므로 이 작업은 항상 건너뜀

<br/>

### 2. 리컴포지션 스킵을 지원하는 매개변수인지 조회하는 작업

- 강한 건너뛰기가 비활성화되어 있고,
- 사용되는 매개변수이고,
- 불안정한 타입의 매개변수이고,
- 기본 인자가 없다면

전체 컴포저블이 리컴포지션 스킵 불가능으로 결정됨

<br/>

### 3. `$changed`와 `$default`에 따라 `$dirty`를 업데이트하는 작업

**1. 리컴포지션 스킵이 이미 불가능하거나, 현재 매개변수가 사용되지 않는다면**

아무것도 하지 않음

**2. 강한 건너뛰기가 비활성되어 있고, 불안정한 타입의 매개변수이고, `$default`가 있고, 기본 인자가 제공되었다면**

람다는 기본 인자를 가질 수 없으므로 이 분기는 항상 건너뜀

**3. 강한 건너뛰기가 활성화되어 있거나, 매개변수의 타입이 불안정하지 않다면**

- `$changed`의 현재 슬롯이 안정하다면
  - 현재 매개변수의 인자 값으로 `changed()` 호출
    - 변경됐다면: `$dirty` 슬롯을 "Different"로 업데이트
    - 동일하다면: `$dirty` 슬롯을 "Same"으로 업데이트

`???` 이외의 분기는 `$dirty` 업데이트 안함???

### 5. skippable 그룹 추가 작업

**1. 리컴포지션을 건너뛸 수 없거나, 모든 기본 인자가 static하다면**

컴포저블이 절대 리컴포지션되지 않으므로 그룹 생성을 건너뜀

**2. \[리컴포지션을 건너뛸 수 있거나, 모든 기본 인자가 static하지 않고], 기본 인자가 하나라도 있다면**

- default group 시작
- `$changed`의 LSB가 1이거나 `$composer.defaultsInvalid`가 true라면, 매개변수를 기본 인자로 다시 초기화
- default group 닫음

<br/>

### 6. 만약 리컴포지션 스킵이 가능하다면

- trackedParameters가 모두 ParamState.Same이고,
- `$changed`의 LSB가 0이라면

리컴포지션 스킵!
